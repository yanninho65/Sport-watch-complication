RÉCAPITULATIF DE TOUT CE QUI A CHANGÉ DEPUIS LE DÉBUT (3 échanges) :

1) Sélecteur de sport puis, maintenant, sélecteur d'API :
   - L'app demande D'ABORD quelle API interroger (`radioApi` :
     TheSportsDB ou Live Tennis API), PUIS quel sport (`radioSportsDbSport`,
     TheSportsDB uniquement — Football/Basketball/Baseball/Hockey sur
     glace/Football US ; le tennis est implicite côté Live Tennis API).
   - Le sport choisi filtre désormais les recherches équipe/joueur/ligue
     de TheSportsDB CÔTÉ CLIENT, sur le champ `strSport` de l'API — pas
     un paramètre d'URL (searchteams.php/searchplayers.php n'en ont pas).
     Avec la clé gratuite, en pratique seul Football renvoie des
     résultats fiables pour les ligues (limite déjà documentée) ; les
     autres sports restent proposés mais peuvent renvoyer 0 résultat.
   - Renommage interne : l'enum qui portait FOOTBALL/TENNIS s'appelle
     maintenant `ApiSource` (SPORTS_DB/LIVE_TENNIS) — son vrai rôle
     étant de dire quelle API réinterroger pour le polling, pas quel
     sport précis a été cherché (TheSportsDB couvrant plusieurs sports
     maintenant). Répercuté partout : MatchResult.source,
     FollowedMatchPrefs, WatchSync, MatchFollowService, et côté montre
     MatchScore.apiSource / MatchListenerService / MatchClock.

2) Clé Live Tennis API : SAISIE DANS L'APP, plus dans le code.
   Comme le dépôt GitHub est public, la clé ne peut plus être en dur
   dans LiveTennisApi.kt (ce qu'elle était depuis la 1ère livraison, en
   valeur "placeholder" à remplacer avant de builder — ce n'est plus le
   cas). Un champ + bouton "Enregistrer la clé" apparaît sur l'écran
   principal une fois "Live Tennis API" sélectionné ; la clé est stockée
   en SharedPreferences locales (TennisApiKeyPrefs.kt, nouveau fichier),
   jamais commitée. Toutes les fonctions de LiveTennisApi.kt reçoivent
   désormais leur clé en paramètre plutôt que de lire une constante.
   Sans clé enregistrée, une recherche tennis affiche directement
   "Renseigne ta clé Live Tennis API ci-dessus" sans appeler l'API pour
   rien ; si la clé est vidée pendant qu'un match est suivi, le
   rafraîchissement périodique échoue silencieusement (comme une panne
   réseau) au lieu de planter.
   Pas de chiffrement (SharedPreferences classiques) — suffisant pour
   l'objectif (ne plus exposer la clé dans le code public), mais pas à
   l'épreuve d'un téléphone rooté. Détaillé dans le README si tu veux
   aller plus loin plus tard (EncryptedSharedPreferences).

3) (Rappel de la livraison précédente, inchangé ici) Le score du set en
   cours en tennis remonte jusqu'à la montre : LONG_TEXT affiche par ex.
   "Alcaraz 2-1 Sinner · 3e set 4-3" pour un match en direct.

À FAIRE avant de builder :
- Ouvrir l'app, sélectionner "Live Tennis API", coller ta clé gratuite
  (inscription sur https://livetennisapi.com/subscribe/free) dans le
  champ qui apparaît, puis "Enregistrer la clé". Plus besoin de toucher
  au code pour ça.

À tester :
- Basculer "TheSportsDB" ↔ "Live Tennis API" doit faire apparaître/
  disparaître le sélecteur de sport TheSportsDB, le champ de clé tennis
  et le sélecteur équipe/joueur/ligue, dans le bon sens.
- Choisir un sport autre que Football sous TheSportsDB puis chercher une
  équipe : la recherche peut renvoyer 0 résultat avec la clé gratuite,
  c'est attendu (voir README) — pas un bug.
- Chercher un joueur de tennis SANS avoir enregistré de clé doit afficher
  le message d'invite, pas planter ni appeler l'API.
